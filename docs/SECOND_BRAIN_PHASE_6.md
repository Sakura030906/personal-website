# 第二大脑第六轮：主动维护与 AI 整理

## 第一轮完成度复核

日常使用闭环和统一知识模型已经形成可持续使用的基础版本：

- 文章、知识节点、项目、阅读记录和文档使用统一实体引用。
- 内容支持草稿、发布、版本记录、恢复和活动审计。
- 收件箱完成“快速记录 -> 整理归档 -> 关联知识”的采集闭环。
- 全站搜索、回顾队列、未来计划和批量复习形成检索与回顾闭环。
- 文章、专栏、知识节点、关系和文档能够进入同一套 RAG 检索范围。

这一阶段已经不是单纯的页面集合，而是可以日常记录、查找、复习和持续积累的数据系统。仍需长期补充的是内容质量、自动化策略和真实使用反馈，而不是底层模型重做。

## 本轮目标

让系统从“等待用户查找和回顾”升级为“主动发现需要处理的知识，并协助用户完成整理”。

## 已完成

### 1. 每周知识报告

- 按 7、14 或 30 天统计真实活动。
- 展示捕获、创建、修改、发布、回顾、活跃天数和触达实体数。
- 使用活动日志生成每日增长趋势、动作分布和实体类型分布。
- 识别最常维护的内容，帮助判断近期精力投入方向。
- 支持复制为可保存的周报文本。

### 2. 知识维护清单

系统会主动识别以下知识债务：

- 已到期但尚未完成的回顾任务。
- 收件箱中长期未整理的记录。
- 没有关系连接的孤立知识节点。
- 缺少摘要或正文的知识节点。
- 长期未更新的内容。
- 解析失败、待处理或需要重新处理的文档。

任务按优先级和类别统一排序，可直接进入整理、回顾或编辑页面。

### 3. AI 辅助整理

- 从收件箱内容生成目标类型、标题、摘要、Slug 和标签建议。
- 自动匹配可能关联的知识专栏和知识节点。
- 默认只生成私有草稿建议，不自动发布，也不直接修改数据。
- 配置真实模型后使用 OpenAI 兼容接口或 Ollama 生成结构化建议。
- 模型不可用时自动降级到本地规则和知识匹配，核心工作流仍可使用。
- 建议可一键带入现有整理表单，由用户确认后保存。

### 4. 主动维护后台

- 后台新增独立“主动维护”页面，不再把功能堆入控制台首页。
- 页面包含周报、增长趋势、知识维护任务和 AI 整理工作台。
- 支持时间范围、任务类型和优先级筛选。
- 桌面端和移动端均使用响应式布局，不产生横向溢出。

### 5. 知识连接巡检

- 扫描知识节点标题、摘要、正文关键词和专栏归属。
- 主动识别标题规范化后相同或内容高度相似的疑似重复节点。
- 排除已经存在的关系，生成新的节点关系候选。
- 关系候选包含原因、置信度和建议关系类型。
- 支持人工确认后建立双向知识关系；疑似重复项只引导人工检查，不自动合并。
- 单次最多分析最近更新的 250 个节点，避免知识库增长后拖慢维护页面。

## API

- `GET /admin/workspace/maintenance?days=7`：返回周报、趋势、维护任务和统计数据。
- `POST /admin/inbox/{item_id}/suggest?mode=auto`：返回 AI 或本地生成的整理建议。

## 安全边界

- AI 建议不会自动发布内容。
- AI 建议不会绕过现有 CMS 的权限、版本和审计机制。
- 关联专栏和节点 ID 会在服务端重新验证。
- 模型返回内容经过字段白名单和长度限制处理。
- 模型不可用时不会阻塞日常采集和整理。
