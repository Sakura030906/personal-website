# 第二大脑第七轮：AI 知识工作流编排

## 本轮目标

把已有的单次 AI 建议升级为可批量处理、可人工确认、可记录结果、可衡量质量的知识工作流。

## 已完成

### 1. 批量整理队列

- 自动读取尚未处理的收件箱记录。
- 单次本地批量分析最多 25 条。
- 真实模型批量分析单次最多 5 条，控制延迟和调用成本。
- 每条建议包含目标类型、标题、摘要、标签、专栏、节点和置信度。
- 模型不可用时继续使用本地规则与知识匹配，不阻塞整理流程。

### 2. 人工确认闭环

- AI 建议支持“采用”和“忽略”。
- 采用后只带入现有整理表单，不会自动创建或发布内容。
- 忽略后从当前确认队列移除，避免重复干扰。
- 每次采用和忽略都会写入活动日志。
- 日志保存建议类型、置信度、建议标识和操作备注。

### 3. 工作流质量指标

- 待确认数量。
- 历史采用率。
- 当前队列平均置信度。
- 标签覆盖率。
- 专栏或节点关系覆盖率。
- 综合整理就绪度。

这些指标来自真实建议与人工决策，不使用虚构的演示数字。

### 4. 知识关系审计

- 从主动维护页确认的知识关系会写入版本与活动记录。
- AI 辅助关系使用独立的 `ai_relation_adopted` 动作标识。
- 关系仍通过标准知识关系接口创建，继续接受节点存在性和重复关系校验。

### 5. 后台工作区

- 主动维护页新增独立的“AI 整理确认队列”。
- 支持刷新、本地批量分析和真实模型分析。
- 原始记录与 AI 建议并列展示，便于人工比较。
- 桌面端保持横向工作流布局，移动端自动改为纵向阅读。

## API

- `GET /admin/workspace/ai-workflow?limit=20`：返回质量指标、待确认队列和最近决策。
- `POST /admin/inbox/suggestions/batch`：批量生成本地或模型整理建议。
- `POST /admin/workspace/ai-workflow/decision`：记录采用或忽略决定。

## 安全边界

- 批量分析不会修改原始收件箱记录。
- 采用建议不会自动发布，只会预填充 CMS 表单。
- 模型批量调用限制为 5 条，避免意外产生大量费用。
- 候选专栏和节点 ID 继续由服务端验证。
- AI 决策完整进入活动审计，不形成不可追踪的后台修改。
